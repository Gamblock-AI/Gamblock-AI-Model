          Simkl API

          Introduction

          We’ve worked very hard to make Simkl the dream "TV, Anime and Movie Tracker". However, chances are it doesn’t do 100% of what you need it to do. Luckily for you, we added an API so you can extend Simkl’s functionality.

          If you need some API method which we do not have, do not hesitate to contact us and we'll add it as soon as possible.

          Useful Links:
          Simkl.com   ∙   Get an API key   ∙   Feature Requests   ∙   Discord Server   ∙   Report Issues   ∙   Twitter

          Getting Started

          This guide will walk you through how to use Simkl API on your website, media server app, browser extension or in your mobile app.

          Before You Start

          To successfully start using Simkl API, you need to:

          1. Sign up for a Simkl account.

          2. Create a new app in your account to get your API key (client_id).

          3. Join the Discord Server to chat

            Join the community to talk, learn about and discuss the Simkl APIs. Or DM directly on Discord.

          Requirements

          1. When using the API, a link is required back to https://simkl.com/ or directly to an item related to the API request. If not sure how to implement, let us know at support@simkl.com or DM directly on Discord.

          2. The Simkl API is not authorized for use in conjunction with other competing services of the same nature if your service or app does not provide Simkl login and Sync functionality with Simkl, including but not limited to TV, Movie, Anime, Manga list/tracker services. If you are interested in using this service within your own application or website, please contact us at though our Discord and we will be happy to discuss it further!

          What this means is that you cannot use parts of the API that don't involve tracking unless you integrate the option to sync with Simkl, especially if your app already has sync functionality with other trackers.

          3. Please use TVDB, TMDB API from their original sources if your need metadata API.

          4. If you're using Github, it is important to hide your Client-ID and secrets in Github Secrets to avoid any API request limit issues.

          5. Free for non-commercial use. (See commercial usage below).

          The Simkl API can be used within commercial applications or services that generate less than $150 per month in revenue free of charge, without explicitly requesting permission. Any application or service that generates more than $150 in revenue per month must obtain a commercial license. Those who wish to acquire a commercial license or more information regarding commercial API usage may reach us through the Discord server.

          Running the API inside your app with large amount of requests costs us fees in DNS, Routing, Health checks, CDN, Server Hosting, Failover backups and Server management so if you have large amount of requests you need to be able to cover them financially.

          How to use the API

          1. Get user's token using OAuth or PIN Authentication and save it on user's device.

          2. Post API requests with the user's token and your API Key (client_id)





          About Simkl API

          All API access is over HTTPS. All responses are returned as JSON. The API is (mostly) RESTful.
          Please contact us if you're interested in an API we don't yet support.

          Verbs

          HTTP Verb Description
          GET Retrieve the item. Success returns 200 status code.
          POST Create a new item. Success returns 201 status code.
          DELETE Delete the item. Success returns 200 or 204 status code.

          HTTP Status Codes

          The Simkl API attempts to return appropriate HTTP status codes for every request.

          Code Text Description
          200 OK Success!
          201 OK Success - new resource created (POST)
          204 OK Success - no content to return (DELETE)
          302 Found Redirected to correct URL
          400 Bad Request The request was invalid or cannot be otherwise served. An accompanying error message will explain further.
          401 Unauthorized Authentication credentials were missing or incorrect.
          403 Forbidden The request is understood, but it has been refused or access is not allowed. An accompanying error message will explain why. This code is used whe using invalid API key or unapproved app or requests are being denied due to API limits.
          404 Not Found The URI requested is invalid or the resource requested. Also returned when the requested format is not supported by the requested method.
          405 Not Found [IN_DEV]
          409 Unauthorized [IN_DEV] Conflict - resource already created
          412 client_id_failed incorrect cliend_id or Total Requests Limit Exceeded
          422 [IN_DEV] [IN_DEV]
          429 [IN_DEV] Rate Limit Exceeded
          500 Internal Server Error Something is broken. Please post to the developer discord so the Simkl team can investigate.
          502 Bad Gateway Simkl is down or being upgraded.
          503 Service Unavailable The Simkl servers are up, but overloaded with requests. Try again later.

          Reference

          Authentication - OAuth 2.0

          There's no reinventing the wheel here so the API uses OAuth2.

          Requesting user associated information requires token that needs to be included in all request headers made to the API.

          To obtain the client_id and client_secret please create an app first.

          To make calls on behalf of a user you have to obtain an access_token. To do this, first use https://simkl.com/oauth/authorize method to get code and then post it in JSON format to https://api.simkl.com/oauth/token url. In response you'll get the access_token. For more details see Authorize and Token sections below.

          So STEP 1 for OAuth - Open the URL that looks like this in your Browser or in a Custom Tab (do not use WebView) on mobile device from your app:

          • Request https://simkl.com/oauth/authorize?response_type=code&client_id=c7be48f1559a6d794w1925237c626326c7bsdfsa559a6d794w1925137c626316&redirect_uri=http://yourdomain.com/oauth.html

          • Response 200

          It will redirect back to your website or app URL with ?code at the end of your Redirect URL.

          Authorize

          Attributes

          Authorize Application

          Redirect a user to this URL. There the user will grant permissions for you app and if everything is fine you'll get a code which you can exchange for access_token. Once you have an access token you can use it to make calls on behalf of a user.

          Note: You should use the https://simkl.com domain when creating this URL and not the API URL.

          Token

          Attributes

          Exchange code for access_token

          STEP 2: The redirect to your application in the step above will include a code parameter which you can exchange for an access_token using this method.

          Save the access_token somewhere safe. From that moment your app can authenticate the user by sending the Authorization header.

          JSON POST DATA

          Key Type Value
          code string code you've get from authorize method
          client_id string Get this in your app settings
          client_secret string Get this in your app settings
          redirect_uri string Your URI in your app settings
          grant_type string authorization_code

          access_token do not have expiration date (Never expire).

          access_token can be deleted by user when revoking app access rights in Connected Apps settings.

          Authentication - PIN

          This flow is designed for devices that have limited input capabilities, such as media center plugins, game consoles, smart watches, smart TVs, command line scripts, and system services, etc. Your app displays an alphanumeric code (typically 5 characters) to the user. They are then instructed to visit the verification URL on their computer or mobile device. After entering the code, the user will be prompted to grant permission for your app. After your app gets permissions, the device receives an access_token and works like standard OAuth from that point on.

          You should do the following step to authorize user's device:

          1. Request a device code.

          2. Display user_code and instruct the user to visit the verification_url.

          3. Begin polling Simkl's authorization server.

          4. User enters user_code at the verification_url on their computer or mobile device.

          5. Simkl returns access_token to the device where the polling is in progress. Your app will be polling to see if the user successfully authorizes your app. Use expires_in to stop polling after that many seconds, and gracefully instruct the user to restart the process. It is important to poll at the correct interval and also stop polling when expired.

          6. Once they have, refresh your UI to indicate a successful connection has been made.

          Request a device code

          Attributes

          Get CODE

          In response you'll get user_code and verification_url (in most cases https://simkl.com/pin/) which should be displayed to the user. Store expires_in and interval values for step 3.

          JSON POST DATA

          Key Type Value
          client_id string Get this in your app settings

          Get CODE status

          Attributes

          Check USER_CODE

          Application can poll this url to get USER_CODE status or ACCESS_TOKEN. Returned interval in step 1 response specifies the minimum amount of time(seconds), that your app should wait between polling requests.

          Calendar

          Simkl provides separate JSON data calendar files that can be used to display the "Upcoming", "Next", "Schedule" or "Calendar" sections in your app or within show details cards.

          The calendar files are generated every 6 hours and are cached on a CDN for 5 hours (you can check the last-modified HTTP Headers for the file generation date).

          The files URLs ignore all query strings, so do not add any additional parameters (such as ?random=***).

          How to use calendar data

          You can use the calendar data to create lists of upcoming episodes, premieres (e.g. S01E01), or movies by combining it with your existing lists or using the user lists obtained from the Sync endpoints.

          Example: When a user opens their watchlist, you can add the calendar data to show that the next episode will air in 3 days, without the need to re-sync the user's list. Simply get fresh calendar files and cache them for 3-6 hours on the user's device.

          List of Calendar Data Files

          Airing Next

          Find out when the next episodes or movie releases are happening:

          https://data.simkl.in/calendar/tv.json
          https://data.simkl.in/calendar/anime.json
          https://data.simkl.in/calendar/movie_release.json

          The calendar files contain episode airing dates (for TV, Anime) and theater release dates (for Movies) for the previous day as well as the next 33 days.

          Monthly Calendar Data Files

          We update calendars for the past 12 months every 24 hours, and for the current month every 6 hours.

          Examples for January 2024:

          https://data.simkl.in/calendar/2024/1/tv.json
          https://data.simkl.in/calendar/2024/1/anime.json
          https://data.simkl.in/calendar/2024/1/movie_release.json

          All calendar items have Simkl rank and ratings, poster images, as well as SIMKL, TVDB, TMDB, IMDB, and MAL IDs where available.

          Attributes

          Ratings by Watchlist

          Attributes

          Get ratings for the watchlist's items

          🔓 Token Required

          When to use it:

          Use this endpoint when you need updated ratings or release status for items in a user’s watchlist. For example, cached data from /sync/ can change over time if show airing statuses or movie release information are updated.

          What you can fetch:

          • Ratings and statuses for movies, TV shows, and anime in a user’s watchlist.

          • Filter by list type (all,watching, plantowatch, completed, dropped, hold).

          • Current release status for each item (e.g., ongoing, released, ended).

          It is highly recommended to cache data for ended TV/anime shows and released movies (or items in the Completed list) for longer periods, as their average ratings and statuses rarely change.

          possible fields values: simkl,link,ext,rank,release_status,year

          release_status Response:

          Below is a table of possible release_status values by media type:

          Type Release Status Meaning
          movie upcoming, rumored, planned, in production, post production,cancelled Various states indicating the movie is not yet fully released or has been cancelled.
          released The movie is already out.
          tv upcoming, planned, in production, cancelled The series is not yet released.
          returning series The series is ongoing, with more episodes/seasons planned.
          ended The series has finished; no new episodes will be released.
          anime upcoming, rumored planned, in production, post production,cancelled The anime is not yet released.
          ongoing The anime is actively airing or has new episodes planned.
          ended The anime has concluded; no new episodes are planned.

          Trending

          Simkl provides pre-built JSON files with trending data ranked by the number of watchers. These are the same rankings displayed on Simkl Most Watched pages for Movies, TV Shows, and Anime.

          Each file is available in two sizes: top 100 (_100) or top 500 (_500) items. Titles with the most watchers are returned first.

          The files URLs ignore all query strings, so do not add any additional parameters (such as ?random=***).

          Update Frequency

          Data Description Update Frequency
          Today Most watched titles over the last 24 hours Every hour
          Week Most watched titles over the last 7 days Once a day
          Month Most watched titles over the last 30 days Once a day
          DVD Releases Latest popular DVD releases (Movies only) Once a day

          All data is cached for 1 hour on Cloudflare (you can check the last-modified HTTP Headers for the file generation date).

          No API key are requred. Please set a User-Agent header with your app name and version (e.g. myapp/1.0) to avoid accidental blocking.

          Scrobble

          Overview

          Simkl stores only one active scrobble session per show/movie/anime. Starting a new session replaces any existing one for that item and clears previous pauses. Paused sessions (created by /scrobble/pause or /scrobble/stop with <80% progress) can be retrieved via Get Playbacks and resumed by calling /scrobble/start with the same item. To delete a paused session, use Delete Playback.

          Typical Flow:

          1. Call /scrobble/start when playback begins.
          2. Call /scrobble/pause to save progress if paused.
          3. Call /scrobble/stop when finished (marks as watched if ≥80% complete).
          4. If activity endpoint has playback updated, retrieve paused sessions with /sync/playback/{type}.
          5. Delete unwanted paused sessions with DELETE /sync/playback/{id}.

          Members can view and manage their saved playbacks at https://simkl.com/my/history/playback-progress-manager/.

          Action Types in Responses:

          • "start" - Returned by /scrobble/start when beginning or resuming playback

          • "pause" - Returned by /scrobble/pause or /scrobble/stop when progress < 80%

          • "scrobble" - Returned by /scrobble/stop when progress ≥ 80% (marks as watched)

          Session Management:

          • Expiry timestamps: Start sessions get expiry = current time + remaining runtime; stop sessions get expiry = current time + 1 hour; pause sessions get expiry = current time

          • Persistence: All sessions persist in the playback until manually removed (no automatic cleanup) or until replaced by next scrobble update for that title, and are retained based on the user's subscription plan: Free (7 days), PRO (30 days), VIP (90 days)

          • Rate limiting: One scrobble operation per user at a time (20-second lock timeout)

          • Duplicate prevention: 409 response if trying to stop an already completed session within 1 hour

          Note: in Sync playback responses, progress is returned as a percentage (float number from 0 to 100, e.g., 0, 45.5, 75, 100). While you can POST 75.00, the response will always be 75.

          Anime Episode Numbering: Simkl uses AniDB as the primary source for anime data, which has different season/episode numbering than TMDB/TVDB. When you send anime scrobbles using TMDB season/episode numbers, Simkl maps them to the corresponding AniDB episode numbers. The response includes both the Simkl\AniDB episode numbers (season, number) and the original TVDB numbers (tvdb_season, tvdb_number) for reference. For example, TMDB Season 2 Episode 4 might map to Simkl\AniDB Season 1 Episode 4, as shown in the anime examples below.

          What is Check-in?

          Check-in is a simple way for users to tell their friends "I'm watching this right now" without requiring a media player or real-time progress tracking. Unlike scrobbling (which requires integration with a media player and only marks as watched after receiving /pause or /stop requests with ≥80% progress), check-in is a manual one time request the user sends to indicate that they're watching something right now and want the Simkl server to auto mark it as watched after the check-in expires (based on runtime).

          Think of it like pressing "I'm watching this" on your remote—one tap and you're done. Simkl takes care of the rest: it shows what you're watching on your profile, and when the movie or episode ends (based on runtime), it automatically marks it as watched. No app running in the background, no progress updates needed.

          Perfect for:

          • 🎬 At the movies – Check in when the film starts, put your phone away, and it's marked watched when you leave

          • 📺 Watching live TV – Cable, satellite, or a friend's streaming account with no Simkl integration

          • 🛋️ Couch mode – Just want to track without installing plugins or using scrobble-compatible apps

          Typical Use Cases:

          • User is watching on a device/service without Simkl integration (cable TV, theater, friend's account)

          • User wants to show on his Simkl profile "Watching Now" bar

          • User prefers manual tracking over automatic scrobbling

          • Social viewing parties or watch-alongs

          How Check-in Works on the Simkl Website:

          Users can manually check in via the "Check in / Watching Now" button found on:

          • Movie pages (example) - Button appears Checkin\Watching Now

          • Episode pages (example) - Button Watching Now on each episode

          When clicked, a popover appears allowing users to:

          1. Optionally set their current progress (via slider or minute input)
          2. Click "Started Watching Now" to check in

          After check-in:

          • The content appears in the user's Dashboard https://simkl.com/my/dashboard/ "Watching Now" bar (visible to friends based on privacy settings)

          • The check-in automatically expires after the item's runtime

          • When expired, Simkl automatically marks the item as watched

          Behavior:

          • Creates a check-in event visible in the user's "Watching Now" bar on the dashboard

          • Session auto-expires based on item runtime (calculated as: now + remaining runtime * (1 - progress/100))

          • The progress parameter is optional (defaults to 0% if not provided). Use it to indicate how far into the content you are when checking in

          • Can be canceled or converted via another /scrobble/stop, /scrobble/pause, or /scrobble/start

          • Calling again with the same item extends/resets the check-in duration

          • When expired, Simkl automatically marks the item as watched (in about 10-120 seconds after 100% progress) and posts to connected social accounts if the user has enabled this option in the sharing settings for example to X.

          Playback

          Attributes

          A playback is a temporary session that stores viewing progress for a movie, TV show episode, or anime episode when playback is paused or stopped before completion. Playbacks are created automatically when users pause their viewing or stop watching before completing an item (less than 80% progress).

          Note: Playbacks are NOT the same as Simkl's sync/watchlist endpoints. Playbacks are temporary pause/resume events and are NOT saved to the user's watchlist. They exist solely to track in-progress viewing sessions.

          ⚠️ IMPORTANT: Always use the Activity API endpoint first to check when you need to refresh sync or playback data. This endpoint provides timestamps for various categories including playback which indicates when playback sessions were last updated. By checking this endpoint first, you can optimize your application's performance and only sync playback data when changes have occurred.

          Relationship to Scrobbling

          Scrobbling and playbacks work together to provide a complete viewing progress tracking system:

          • Scrobbling (/scrobble/start, /scrobble/pause, /scrobble/stop, /scrobble/checkin) is the action of reporting real-time playback progress to the API

          • Playbacks are temporary records created by scrobble pause/stop actions, storing pause points that can be resumed later

          • Sync/ endpoints (like /sync/all-items) are for permanent watchlist records that track what users have watched

          How they connect:

          1. When a user calls /scrobble/pause, it creates a temporary playback record with the current progress (not added to watchlist)

          2. When a user calls /scrobble/stop with less than 80% progress, it creates a temporary playback record (not added to watchlist)

          3. When a user calls /scrobble/stop with 80% or more progress, the item is marked as watched in the user's history/watchlist (no resumable playback is created)

          4. The /sync/playback/{type} endpoint retrieves these temporary playback records so apps can display "Continue Watching" lists

          5. Users can resume a saved playback by calling /scrobble/start with the same item

          Key differences from sync watch history endpoints:

          • Playbacks (/sync/playback) = Temporary pause/resume events for in-progress viewing (NOT on watchlist)

          • Sync (/sync/all-items) = Permanent watchlist records for completed items (≥80% progress)

          • Only one playback session per item is stored (the most recent pause point)

          • Playback sessions persist in the database until manually deleted or until /scrobble/start is called for the same item

          • When retrieved via GET, sessions are automatically filtered out if the user has already watched the item after the playback was created (but remain in the database)

          Retention periods by subscription plan:

          Playback progress records are automatically retained based on the user's subscription level:

          • Free users: 7 days retention

          • PRO users: 30 days retention

          • VIP users: 90 days retention

          These retention periods determine how long paused playback sessions remain available for the user to resume.

          Users can view and manage their saved playbacks at https://simkl.com/my/history/playback-progress-manager/.

          Error Responses

          The API uses standard HTTP status codes to indicate the success or failure of a request.

          Status Code Meaning Description
          201 Created Success The scrobble event was successfully created.
          204 No Content Success The playback session was successfully deleted.
          400 Bad Request Client Error The request was malformed. This can happen if you send a scrobble request without a movie, show, or anime object, or if there's a concurrency issue (see Rate Limiting).
          401 Unauthorized Client Error The provided access token is invalid or has expired.
          404 Not Found Client Error The requested item (movie, show, episode) could not be found on Simkl, or the URL is incorrect.
          409 Conflict Client Error Returned by /scrobble/stop if you try to scrobble an item that was already marked as watched within the last hour. The response body will contain watched_at and expires_at timestamps.

          Session Expiry & Storage

          • start sessions have an end_on timestamp set to current time + remaining runtime, but are not automatically deleted when expired

          • stop sessions have an end_on timestamp set to current time + 1 hour, but are not automatically deleted when expired

          • pause sessions have an end_on timestamp set to current time, but are not automatically deleted when expired

          • All playback session types persist in the playback until manually removed via the DELETE endpoint, or by the user, or until they are replaced by the next scrobble update for that title

          The runtime in minutes is determined as follows:

          • Movies: Uses the movie's runtime from Simkl's database. Defaults to 90 minutes if not available.

          • TV Shows: Uses the episode's specific runtime. Defaults to 45 minutes if not available.

          • Anime: Uses the episode's specific runtime. Defaults to 25 minutes if not available.

          Concurrency & Rate Limiting

          To ensure data integrity, the API processes scrobble events sequentially for each user. If you send multiple requests at once, they will be queued. A request may time out and fail with a 400 Bad Request error if it has to wait too long for the previous one to complete. We recommend queuing scrobble events in your application and sending them one by one.
